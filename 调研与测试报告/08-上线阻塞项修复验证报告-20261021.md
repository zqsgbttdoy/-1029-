## 二、XSS 修复（P063 / P064 及其它风险点）

### 2.1 safety-log.html（安全日志）

- 新增统一编码助手：`esc()`（优先复用 `App.escape`，回退为 `& < > " '` 全量实体编码）与
  `jsAttr()`（先转义反斜杠/单引号/换行，再做 HTML 实体编码，专用于 inline `onclick` 的 JS 字符串上下文）。
- 列表渲染 `renderTable()`：`code / project / date / author / reviewer / status / statusText` 全部经 `esc()` 输出。
- 项目下拉 `loadProjects()`：`projectFilter`、`projectSelect` 的 `value` 与文本均经 `esc()`。
- 查看版本面板 `buildViewVersionPanel()` 与编辑版本面板：提交人、提交时间、驳回原因/人/时间、工程名称、日期、
  填写人、审核人、天气/风力/气温、施工部位、巡视检查、安全处理结果、重大事项、照片 `data-url/data-name/src/alt/名称/时间`、
  附件名/大小/时间全部编码。
- 历史版本时间线 `renderViewVersionHistory`：提交人/时间、正文、驳回原因、驳回人/时间改为 `esc()`。
- 附件回显（编辑态）`populateUploadAreas`：附件名与照片 `src` 编码。
- 新建附件 `handleCreateFile`：文件名文本用 `esc()`，`openDirSelector('...','...')` 参数改用 `jsAttr()`。
- 目录选择 `updateSelectedDirList`：标签文本用 `esc()`，`removeDirTag('...')` 参数改用 `jsAttr()`。
- 照片预览 `viewPhoto`：`src / alt / 文件名` 编码。

### 2.2 project-ledger.html（项目台账）

- 删除按钮改为 `confirmDelete(' + d.id + ')`，**只传数字主键**，不再把项目名塞进 onclick 的 JS 字符串。
- `confirmDelete(id)` 在函数内部从 `allData` 反查项目名，确认文案仍用 `textContent` 赋值，
  即使项目名含 `');window.__qaXss=1;//` 也无法突破字符串上下文。

### 2.3 operation-log.html（操作日志）

- 列表行 `time / operator / module / content / ip` 及未命中类型映射时的 `opType` 回退值全部经 `esc()` 输出。

### 2.4 log-statistics.html / safety-log-statistics.html（统计页）

- 提交详情弹窗中的 `项目名称 / 提交人 / 提交时间` 改为 `App.escape()`。
- 列表中的 `submittedAt` 同步编码。

## 三、统计 / 报表口径修复（P030–P039、P040–P047）

### 3.1 监理日志统计、安全日志统计

- **草稿不算已提交**：`todaySubmitted` 仅在状态非空且不属于 `draft/unsubmitted` 时置真。
- **应写天数去重**：按 `项目 + 日期` 建立 `days` 集合，同一天多条记录只计 1 天；`passed` 同样按
  `项目 + 日期 + approved` 去重。
- **无记录项目纳入统计**：`aggregate()` 先按 `projectsMap` 预建分组，再叠加日志，未写日志的项目显示为「未提交」。
- **分页不静默少计**：`loadData()` 改为分页循环取数（`pageSize=2000`，最多 20 页），
  当累计条数仍小于接口 `total` 时输出 `console.error` 显式暴露截断风险，不再静默丢弃。
- 完成率在 `totalDays=0` 时按 0% 处理，避免 `NaN%`。

### 3.2 日记统计

- 卡片仍按「记录条数」统计已通过/草稿，便于核对；表格改为按 **人员 + 日期** 去重：
  `应写天数`、`已通过`、`被驳回` 均为去重后的天数，同人同日多条不再重复计 2 天。
- `loadData()` 分页循环取数（`pageSize=1000`，最多 20 页），超限时 `console.error` 显式告警。

### 3.3 日记报表

- 数据映射保留记录 `id`，「查看日记」链接改为 `supervision-diary.html?readonly=true&id=<记录ID>`。
- 分页循环取数，避免 1000 条以上记录被静默截断。
- CSV 导出新增 `csvCell()`：含逗号、双引号、换行的字段自动加引号并双写内部引号，防止列错位；
  表头同样走统一转义。

## 四、权限矩阵缺口（D3）

用户验收口径为「普通用户禁止访问管理接口」+「admin 角色不可删除且始终拥有全量权限」，均已验证：

- `RoleController / PermissionController / DepartmentController` 整类标注 `@RequireRole("admin")`。
- 集成测试 `PermissionAuthorizationIntegrationTest`（17 项，本轮全绿）覆盖：
  - `normalUserCannotAccessAdminEndpoints`：普通用户 GET `/roles`、`/permissions`、`/permissions/tree`、
    `/departments`、`/departments/{id}` 及写接口全部 403；
  - `adminRoleAlwaysKeepsAllPermissions`：即使提交空权限数组，admin 角色仍保留全部权限；
  - `adminRoleCannotBeDeleted`：删除内置 admin 角色返回 400「系统管理员角色为内置角色，不可删除」。
- 端到端追加核验（`D3D4核验.txt`）：新建只读角色 + 普通用户后，`/roles`、`/permissions`、`/departments`
  实测均返回 403；admin 角色删除返回 400；admin 权限绑定 31/31。

## 五、单据正文锁定与乐观锁（D4）

### 5.1 正文锁定

`SupervisionNoticeService.update()` 与 `WorkContactService.update()` 增加：
- 状态属于「已下发/已发送/已逾期/已回复/已验证」时，正文与原值不一致直接返回 **409**，
  提示「正文不可覆盖，如需修正请新建修订版本」；
- 状态流转白名单：通知单 `draft→issued`、`issued→overdue`、`responded→verified`；
  联系单 `draft→sent`、`sent→overdue`、`replied→verified`；其余跳转返回 **409**。
- 仅锁定正文 `content`，不锁定标题/编号，保持既有单测 `testUpdateWithSameCode` 等行为不变。

### 5.2 乐观锁

- 现场记录沿用 `FieldRecord.lockVersion` + `X-Record-Version`：缺失版本返回 428，版本不一致返回 409
  （`FieldRecordService.locked()`，悲观写锁 + 版本比对）。
- 端到端实测（`D3D4核验.txt`）：创建日记 `lockVersion=0` → 正确版本更新后 `1` → 用旧版本 0 再次更新返回 **409**
  → 不带版本头返回 **428**。
- qa22 系统测试 T214/T226（已下发/已回复正文可覆盖）由「失败」转为「通过」。
