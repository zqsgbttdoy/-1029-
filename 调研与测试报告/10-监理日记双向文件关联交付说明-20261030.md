## 二、功能行为

### 2.1 填写指引（PC `supervision-diary.html` / 小程序 `pages/record`）
- 新建及重开可编辑日记时，自动按“日记日期”加载同项目五组来源：日常巡检、旁站检查、监理通知单、工作联系单、工程资料。
- 五组各自独立：开始/结束日期、编号或标题关键词、本页附件名筛选、翻页、加载中、空结果、失败重试互不影响；
  筛选条件变化只废弃本组请求，不取消其他四组。
- 每个来源条目列出真实附件；来源记录没有实际附件时明确显示“无可关联文件”，不伪造 PDF/Word，也不把详情页当作原件。
- “复制链接”复制稳定地址（同源 `file-reference.html?...`）；HTTP 下剪贴板不可用时展开只读文本框供手动选择复制。
  **查询、复制、打开均不建立引用**，只有正文保存到服务器后才计数。

### 2.2 正文编辑（九个长栏）
- 九个栏目（施工部位、施工管理、监理工作、其他工作、其他事项、晨会、新问题、材料进场检查、图纸审查）
  使用“文字节点＋文件节点”混排组件；短字段、日期、人员字段不改。
- “填写人/记录人”继续由登录身份只读显示，链接不写进人员字段。
- 支持光标位置插入、复制/粘贴、删除、撤销/重做、中文输入法组合输入；文件节点不可被局部编辑成另一个目标。
- 撤销/重做由组件自持快照栈（最多 50 步），粘贴文字与异步授权转换合并为同一次编辑，
  不会撤销回退成可见的裸地址；组合输入整体作为一个撤销单元。
- 剪贴板 HTML 只抽取文字与受信任链接，脚本、事件属性、`javascript:` 等危险协议降级为普通文字；
  授权或解析失败时保留用户原输入并提示“链接未转换”，不丢字、不伪造成成功。
- 组合输入未结束、单栏超 60000 字符时拒绝保存并保留内容；整篇超过 200 个不同来源文件时服务端拒绝，不截断正文。
- 异步资源加载与链接授权绑定账号、项目、草稿与输入版本，关闭/切换/保存/换账号后的迟到响应不会回填旧稿。

### 2.3 工程资料反查（`project-data-upload.html` / `pages/project-documents`）
- 文件条目显示“被 X 篇监理日记引用”，0 篇不显示；计数按当前页批量聚合，不逐文件请求。
- 点击展开分页引用列表，跳转 `supervision-diary.html?id=…&readonly=true`（小程序为
  `/pages/record/index?kind=supervision-diaries&id=…&readonly=true`），只读且不因作者是本人而自动建本机草稿。
- 返回、下拉刷新、窗口重新聚焦时重新取数；项目/目录切换、账号切换、卸载后的迟到响应被丢弃，不显示上一项目的计数。
- 列表为真实分页（每页 20 条），引用列表 10 条分页，不是只展示前 200 条。

### 2.4 失效与删除
- 资料删除或来源移除/替换附件：日记正文不改写，原位置标记“资料已删除／不可用”，不再计入有效引用；
  失效链接可原样保留并继续编辑无关文字。
- 已签发的旧下载地址在资料删除后实际读取返回 404，上传者身份不能绕过“来源已删除”的检查。
- 删除日记（现有逻辑删除）在同事务清除当前关系，历史事件快照仍保留。
- 同一物理文件经多个有效来源引用时，反查按同项目规范化文件身份 `COUNT(DISTINCT diary_id)` 汇总。

## 三、接口契约

| 接口 | 说明 |
| --- | --- |
| `GET /field/diary-resources` | 必传 `projectId`、`sourceType`（五源白名单）；可选 `date`/`dateFrom`/`dateTo`/`keyword`/`pageNum`/`pageSize`。未给范围时按 `date`（缺省当天）；开始晚于结束返回 400。默认每页 20 个源条目、上限 100，返回 `list/total/pageNum/pageSize`，条目含来源类型、ID、编号/标题、业务日期、文件数组（来源定位、规范化路径、文件名、类型、稳定链接）。 |
| `GET /files/reference-access` | 按 `sourceType/sourceId/file` 返回稳定定位、文件名/类型、`projectId` 与**仅当次可用**的 120 秒签名地址；定位必须与源记录的精确文件绑定一致，不接受仅凭文件名、同项目或任意 URL。 |
| `GET /files/content` | 票据 v2 增加来源定位，读取时重新核验源存在、精确绑定与当前用户/项目权限；兼容旧票据。`text/*` 在完整通过 UTF-8 校验后声明 `charset=UTF-8`（不转码、不改原字节），非 UTF-8 文本保留原编码行为。 |
| `GET /project-documents` | 原有字段与分页不变，新增只读 `diaryReferenceCount`（按当前页批量聚合）。 |
| `GET /project-documents/{id}/diary-references` | 先校验资料与项目权限，再按与日记列表一致的可见性查询有效关系，返回去重后的日记 `id/code/diaryDate/authorName/status` 与总数。 |
| `/field/diary-source`、`/field/diary-prefill` | **契约保持不变**，继续服务监理日志整编/预填。 |

稳定链接格式：`file-reference.html?sourceType=…&sourceId=…&file=…`（三个参数严格编码、仅同源相对路径）。
正文落库仍为文本，固定语法 `[文件名](稳定链接)`，支持括号/方括号/反斜杠转义；历史裸 URL 不会被批量推断为引用。

## 四、数据一致性、权限与并发

### 4.1 关系表
`biz_diary_reference`：`id/project_id/diary_id/source_type/source_id/file_key/file_url/file_name/active/inactive_reason/create_time/update_time`，
`file_key` 为规范化路径的 SHA-256，比较时同时核对原路径；唯一键 `(diary_id, source_type, source_id, file_key)`；
反查索引 `(project_id, file_key, active, diary_id)`；源生命周期索引 `(source_type, source_id, active)`。**不存累计篇数字段。**
`schema.sql` 与 `schema-field-workflow.sql` 同步加入可重复执行的关系表与索引。

### 4.2 正文为唯一依据
- 不新增富文本正文列，不存任意 HTML；`FieldRecordService` 在日记创建/更新事务内解析最终九栏正文，差量同步关系，
  随后记录原有事件快照；提交/审核不扩大权限。
- 移除链接后保存立即移除关系；只删同一文件的一个重复位置不减少篇数；失败、回滚、幂等重试与版本冲突不改变有效引用、不产生重复行。
- 修订稿继承失效链接须证明原稿可见且本人已审核；不能借此新建越权有效关系。

### 4.3 锁顺序与生命周期
- 统一锁顺序：**日记行 → 稳定排序的来源行 → 上传文件 → 关系行**。`FieldRecordService` 在 `attachments.bind` 之前调用
  `diaryReferences.lockSources`；取到源锁后 `refresh`，避免一级缓存还原并发删除前的绑定。
- 来源写入口（巡检、旁站、资料、通知单、联系单及通知回复/复核合并）在原写事务内按源定位把不再绑定的关系置为失效，
  不反向修改日记；追加新附件不会复活旧失效引用。
- 可见性统一由 `FieldRecordVisibility` 判定：他人 `draft` 不计入计数、不出现在反查列表，审核员也不能通过计数推断他人草稿。

## 五、本轮发现并修复的真实缺陷

1. **浏览器原生撤销会退回裸地址**：异步授权把粘贴占位符替换成文件节点后，原生 undo 栈仍保留 fallback 文本，
   撤销会把文件节点退回裸地址（正文与引用不一致）。改为组件自持受控快照（DOM + 正文 + 选区路径），
   拦截 `Ctrl/Cmd+Z`、`Ctrl+Y`、`Shift+Ctrl/Cmd+Z` 与 `beforeinput historyUndo/historyRedo`，粘贴与授权转换合为一次编辑；
   恢复快照仍引用 `entries` 中的不可变源定位。真实浏览器已验证“输入文字后撤销仍保留文件节点”“再次撤销回到粘贴前”“重做恢复”。
2. **中文文本原件显示乱码**：`/files/content` 原按 `text/plain` 无字符集返回，浏览器按本地旧编码解析 UTF-8 文件。
   现对完整通过 UTF-8 校验的 `text/*` 声明 `charset=UTF-8`，原文件字节不变；新增“UTF-8 声明且字节不变”
   “GB18030 不误标 UTF-8 且字节不变”两项控制器测试。真实浏览器登录后打开原件已显示正确中文。
