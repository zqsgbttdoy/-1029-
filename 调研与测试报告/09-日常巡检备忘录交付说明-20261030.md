## 二、本轮发现并修复的真实缺陷

**PC 端已保存巡检点“保存修改”实际不生效（编辑器不关闭、列表不刷新）。**

- 现象：PUT `/api/daily-inspections/{id}` 已返回 200，数据库也已更新，但页面停在编辑器，无成功提示，
  也无列表刷新请求；用户误以为未保存而反复操作。
- 根因：`补后端/assets/field-records.js` 保存成功后的“请求是否被篡改”比较基线写死为 `status:'draft'`，
  而巡检保存修改提交的状态是 `recorded`，`C.sameBody` 逐字段比较含 `status`，判定不一致后走
  “此前未确认的请求已恢复…”分支 `return`，跳过了关闭编辑器与刷新列表。
- 修复：基线按当前操作预期终态取值
  `const current = pack(kind, Object.assign({}, draft.body, { status: memo ? 'recorded' : 'draft' }));`
  其他四类记录仍用 `draft`，幂等/丢响应比对强度不变。
- 回归：`drafts.test.cjs` 新增用例“电脑端已保存巡检保存修改后关闭编辑器并留在已保存”
  （PUT 体 `status=recorded`、不调用 `/submit`、编辑器关闭、提示“巡检修改已保存”、列表仍为已保存、本机草稿已清除）；
  浏览器脚本新增“再次打开保存修改仍为已保存且不进入审核”“关闭不保存时列表不新增记录且本机暂存已丢弃”
  “375 宽下逐字段单列、无横向溢出”三项断言。

## 三、行为变化清单

### 3.1 服务端
- `FieldRecordKind`：DAILY 标记为无需审核；`recorded/submitted/pending/approved/rejected/fixed/active` 历史状态
  统一按“已保存”读取、筛选与判定可编辑；`draft` 仍是私有草稿，`inactive` 仍不可见，NULL/未知状态不外扩权限。
- `FieldRecordService`：DAILY 的 `/submit` 走完整校验后落为 `recorded`，不伪造审核人/时间；再更新始终保持
  `recorded`（旧客户端传 `draft` 也不退回草稿、不换编号）；`/approve` 对 DAILY 返回 400“日常巡检无需审核”；
  已保存 DAILY 仅本人可改，项目归属不可更换；保留操作事件快照与历史。
- `/field/summary`：DAILY 只输出草稿数、已保存数，审核相关计数为 0；其他类型统计不变。
- `AttachmentAccessService`：当前记录与历史快照沿用同一状态策略，仍按精确文件引用 + 短时签名授权。

### 3.2 PC（`补后端/assets/field-records.js`、`daily-inspection.html`、`process-management.html`）
- 状态筛选“全部/草稿/已保存”；列表、详情、摘要、CSV、打印显示“已保存”。
- 新建/草稿保留“保存草稿”“提交”；已保存只显示“保存修改”，隐藏保存草稿、审核通过/退回、删除、建立修订稿；
  历史面板仍显示真实旧事件。
- 提交不弹审核/正文锁定确认；成功后关闭弹窗、回到列表首页并按需重置项目/日期/编号/状态筛选以展示刚保存记录。
- 校验失败、上传失败、并发冲突或有未确认问题编辑时不关闭、不提示成功；关闭视为放弃本次编辑。
- 流程管理页巡检示意卡改为“现场备忘录保存”，不再提供巡检审批配置。

### 3.3 小程序（`utils/schema.js`、`utils/drafts.js`、`pages/record/*`、`pages/home/*`）
- 记录页：巡检隐藏审核入口，提交按钮按类型显示“提交/保存修改”，提交成功无审核弹窗并返回首页；
  已保存可再次编辑，仍为 `recorded`。
- 首页：不对日常巡检展示“项目待审核”，切到巡检从待审核待办回到“我的记录”；摘要只显示草稿/已保存。
- 说明文案去掉“改变审核状态”等不适用措辞。

## 五、上线步骤与授权边界

1. **先备份**：正式库在做任何结构/数据操作前完成可回滚备份，并保留校验记录。
2. **在副本验证补列**：`schema.sql`（新库）与 `schema-field-workflow.sql`（幂等补列）中的新字段均为可空列，
   先在数据库副本执行并核对列、索引与旧数据只读表现，确认无误再考虑正式库。
3. **前后端同步发布**：`补后端/assets/*.js|css` 与 HTML 属静态资源，后端 `FieldRecordKind`、
   `FieldRecordService`、`AttachmentAccessService` 等属 Java 变更，**必须同批发布，不能只靠 Ctrl+F5**；
   只发前端会得到“前端认为已保存、后端仍按审核处理”的不一致结果。
4. **正式迁移与重启另行授权**：本轮未连接生产 MySQL、未启动 local profile、未执行任何存量库迁移、
   未重启 8080/8081。正式补列、数据迁移与服务重启需单独授权与窗口。
5. **小程序发版**：需重新上传审核发版后生效；本轮仅完成逻辑/组件测试（`drafts.test.cjs`），**未做真机验证**。

## 六、本轮未做（明确的边界）

- 不删除历史待审核/通过/退回记录，不重写其审核事件；只改变读取与可编辑判定。
- 不为已保存巡检新增删除能力，不放开“建立修订稿”；不把全局审核能力或项目审核权限删除。
- 不新增检查项模板管理、通知单关联、整改回复/复查闭环，不新增单位工程树/危大工程等链路。
- 巡检不新增 Word 导出；CSV 仅导出服务器筛选结果，附件只列名称、不含访问令牌。
- 未提交、未推送、未部署；工作区保留改动待评审。
