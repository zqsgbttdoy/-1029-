# 微信小程序部署与首期验收指南

## 一、当前交付范围
原生工程位于 `miniprogram/`，不是将 PC 页面套入 WebView。PC 与小程序使用同一后端、数据库、项目授权、审批状态和附件规则。

- 首期页面：账号密码登录、我的项目、四类现场记录（日记、日志、日常巡检、旁站）、本人草稿、待审核列表、今日可见记录摘要。
- 填报能力：分栏目文字、可选语音转文字、拍照／相册、照片说明、持久本机草稿、前台恢复网络同步、提交、通过／退回、修改再提交。
- PC 四个原有业务 URL 接入 `assets/field-records.js`；支持多份本机草稿恢复、处理历史、修订稿、CSV 和打印。
- 日记取数已移到后端：单一真实项目 ID、单日、已通过记录；排除已被通过修订稿替代的原件，保留来源。两端只补空白栏目，不覆盖手填内容，失败不产生模拟数据。
- 未纳入首期：订阅消息、施工单位外部账号、自动月报、完整整改移动闭环、后台常驻上传、完整离线数据库、电子签章。
- 摘要是按权限可见的记录数量，不等于全项目“应填／未填人数”或整改未闭环统计。

此前“后端零代码改动”的结论仅适用于基础 JSON/JWT 接入，不适用于完整移动办公。当前版本已新增项目成员、并发版本、幂等和审计表，必须先完成数据库升级。

## 二、先完成后端升级
1. 备份现有数据库和上传目录，在数据库副本演练；安排维护窗口停止旧版 PC 与旧后端写入。
2. 已有库使用维护账号执行 `backend/src/main/resources/schema-field-workflow.sql`。在 MySQL 客户端先 `USE` 目标库，再 `SOURCE` 脚本。不要在已有库重复导入含示例账号的 `schema.sql`。
3. 全新测试库可用更新后的 `schema.sql` 建表。其示例账号只用于演示，生产不得保留默认账号密码。升级脚本可重跑，但不会修正任意手工修改过的字段类型；执行后仍须启动校验。
4. 检查升级脚本输出的状态和作者缺失记录。`pending` 兼容待审核，`recorded/fixed` 仅保留存量只读；`active`、NULL 或未知状态须由业务负责人核对，不得自动视为通过。已有缺失业务版本初始化为 1，并发版本新增为 0。
5. 新增 `biz_project_member`、`biz_uploaded_file`、`biz_field_record_event`；四类表新增同步元数据，日志新增 `diary_sources`。不要以 `ddl-auto=update` 替代升级，生产继续 `validate`。
6. 更新后端、四个 PC 页面、`assets/` 及 PC 依赖的 `miniprogram/utils/schema.js`。它是共用字段模块，不能只上传 HTML。
7. 填好 `deploy/supervision.env.example` 的八项必填值。新增 `APP_UPLOAD_SIGNING_SECRET` 至少 32 字符，独立随机生成，不复用 JWT 密钥。多实例使用同一密钥及共享上传存储；轮换密钥后旧短链失效。
8. 应用 `deploy/nginx-supervision.conf` 并按部署流程校验。`/api/uploads/` 和 `/uploads/` 禁止直出，JS/CSS 重新验证缓存。历史客户端已有长缓存时，发布时安排强制刷新或清理 CDN 旧缓存。
9. 上传目录位于静态站点根目录之外，静态部署不得包含 backend、deploy、密钥、日志和数据库文件。数据库及文件备份必须配套恢复。

DDL 隐式提交，不能依靠事务回滚恢复旧结构。失败时停止发布，根据实际结构修复后重试；需要退回旧版本时使用维护窗口内的备份恢复方案，禁止直接删除新表中的审计数据。当前迁移脚本尚未在真实 MySQL 实例执行验证。

## 三、账号、项目与流程
- 登录继续使用已有业务账号，不把微信身份当作系统权限。
- 项目访问与审核由“权限设置”、人员管理的项目分配及管理员接口维护；现场记录页的“项目成员授权”按钮已下线，避免与“权限设置”重复。
- 兼容人员台账 `projectId` 和项目负责人；显式停用成员优先，负责人也可被撤销该项目权限。总监无需因此获得系统管理员角色。
- 作者由登录身份生成；仅本人可修改草稿／退回稿。审核人可查看已提交待办，不能读取他人未提交草稿。已通过记录可按项目权限查阅。
- 状态统一为 `draft → submitted → approved/rejected`；退回后修改再提交。通过原件锁定，修订另建并保留来源和历史。
- 本机半填表单可随时暂存；服务器草稿仍需满足基础字段格式，正式提交进一步校验正文。日记要求天气和照片；旁站要求部位、起止时间、工序、结果、关联资料和非负整数人员数量。
- 历史事件包含操作者、动作及正文快照，不允许经普通业务接口编辑；它不等同于合规电子签章或不可篡改取证。

## 四、导入原生小程序
1. 微信开发者工具导入 `补后端/miniprogram`。将 `project.config.json` 的 `touristappid` 改成单位真实 AppID。
2. 在 `config.js` 设置 `baseUrl: 'https://your-domain.com'`，不要追加 `/api`；提交真实发布配置前检查 HTTPS 证书及证书链。
3. 微信公众平台“开发管理 → 开发设置 → 服务器域名”配置同一 HTTPS 域名的 `request`、`uploadFile`、`downloadFile`。这里只填域名，不带业务路径；按本项目模板使用标准 HTTPS 443。
4. 核验主体、服务类目、域名备案、小程序备案、适用认证、隐私保护指引，以及拍照／相册、录音等接口的最新平台要求。限制和可用能力以发布时微信后台为准，不承诺审批周期。
5. 关闭开发者工具的“不校验合法域名”开关后编译，并在 Android、iPhone 测试。开发工具放行不能作为真机或发布验收依据。

主要文件：
- `pages/login/`：账号登录。
- `pages/home/`：项目切换、记录／待办、草稿、摘要。
- `pages/record/`：四类表单、照片、语音入口和审核。
- `utils/api.js`：鉴权、分页、上传、受控链接、账号检查。
- `utils/drafts.js`：账号隔离本机草稿、持久照片和同步重试。
- `utils/schema.js`：两端共用字段及巡检／旁站内容转换。

### 可选语音
默认 `voiceEnabled=false`，文字填报可独立使用。开通步骤：
1. 在当前小程序后台添加微信同声传译插件，并确认主体／类目允许使用。
2. 按微信后台显示的已获授权插件 provider 和版本，在 `app.json` 的 `plugins` 中声明名称 `WechatSI`；不要猜测版本或直接复用其他单位配置。
3. 设置 `config.js` 的 `voiceEnabled=true`，完成录音隐私声明和授权验收。
4. 每段最多 60 秒，识别文字由本人核对后追加，特别注意轴线、强度、尺寸和数字。失败或拒绝录音时可直接输入；离线不支持语音识别。服务器不保存原始音频。
5. 页面隐藏／退出时取消待授权录音并结束已启动录音；迟到授权及旧识别结果不回填。核对弹窗期间切换账号或离开页面，也不会将识别文字写入旧稿。仍须按已授权插件版本完成真机验证。

平台参考：[语音插件](https://developers.weixin.qq.com/miniprogram/dev/platform-capabilities/extended/translator.html)、[文件系统](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/file-system.html)、[运行机制](https://developers.weixin.qq.com/miniprogram/dev/framework/runtime/operating-mechanism.html)、[隐私保护](https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/)。

## 五、接口契约与附件
所有业务路径前缀 `/api`，JSON 响应 `{code,message,data}`，分页 `data={list,total,pageNum,pageSize}`。请求带 `Authorization: Bearer …`；令牌默认 24 小时，到期重新登录，不删除原账号草稿。小程序原生网络请求不使用浏览器同源模型，仍须配置合法域名；PC 的 CORS 也不能关闭。

四类路径：`supervision-diaries`、`supervision-logs`、`daily-inspections`、`sideline-inspections`。

| 操作 | 方法与路径 | 必需信息 |
| --- | --- | --- |
| 新建 | `POST /api/{类型}` | `Idempotency-Key`：16–100 位字母／数字／下划线／连字符；一个新请求一个 key |
| 保存 | `PUT /api/{类型}/{id}` | `X-Record-Version`：上次响应的 `lockVersion` |
| 提交 | `POST /api/{类型}/{id}/submit` | 同上 |
| 审核 | `POST /api/{类型}/{id}/approve` | 同上；正文 `status=approved/rejected`，退回需 `rejectReason` |
| 删除草稿 | `DELETE /api/{类型}/{id}` | 同上，仅可编辑原件 |
| 历史 | `GET /api/{类型}/{id}/history` | 当前记录查看权限 |
| 摘要 | `GET /api/field/summary?projectId=…&date=YYYY-MM-DD` | 项目权限 |
| 日记来源 | `GET /api/field/diary-source?projectId=…&date=YYYY-MM-DD` | 单日、已通过；超过500份明确拒绝截断取数 |

新建重试必须保持原正文与 key，不能用同一 key 发不同内容。409 表示版本／重复请求内容冲突，428 表示缺少版本；不得直接取新版本强行重发覆盖。`version` 是业务修订号，不是并发版本。来源 `diarySources` 是 JSON 字符串，保存时由服务器校验项目、日期和来源版本。

附件流程：
1. `POST /api/files/upload`，multipart 字段固定 `file`，返回 `{url,name,size}`。不要手动设置 multipart Content-Type。`wx.uploadFile` 的响应字符串需解析。
2. 原始 `url` 存入记录 `photos/attachments` 的 JSON 文件列表，可含 name、description、source、capturedAt；先上传不等于记录已保存。
3. 查看时带登录令牌请求 `GET /api/files/access?url=…`，获取有效 120 秒的 `/api/files/content?...` 链接，再拼域名展示／下载；短链不得写回业务字段。
4. 内容访问会再次检查账号状态和当前项目授权；撤销项目成员后，原签名链接也不能继续取文件。不要分享短链或将其记入公开日志。
5. 原始路径不会公开展示。兼容 `uploads/`、`/uploads/`、`/api/uploads/` 的安全路径；历史文件须位于配置上传根目录且存在授权业务引用。任意绝对磁盘路径不开放，应核对后重新上传／迁移。
6. 工程资料仍需选择本项目有效子项；资料作者由登录身份确定。

后端单文件上限默认 50MB、单请求 100MB，Nginx 默认 100m；实际还受扩展名白名单、微信版本、网络超时和存储限制。小于上限不代表必定上传成功。受控响应 `Cache-Control: private, no-store`，不再使用公开文件30天缓存。

## 六、离线与并发边界
- 必须事先成功登录并缓存获授权项目。文字与照片仅在当前手机暂存；照片复制到 `wx.env.USER_DATA_PATH`，不是只保存临时路径。
- 显示“仅本机保存／待同步／已同步草稿／已提交／同步失败／内容冲突”；只有服务器确认后显示提交成功。
- 网络恢复且小程序在前台时保存服务器草稿；正式提交仍由本人确认。关闭微信后不承诺继续上传。
- 请求响应丢失重放原请求。上传失败保留照片与草稿；400等明确拒绝可纠正正文；409保留双方内容，人工对照，不能最后写入覆盖。
- 草稿按业务账号和 API 域名隔离，账号切换不会加载前一账号数据。原账号登录后恢复；不要为解决登录失效清空微信数据。
- 存储不足时留在当前页重试，当前运行期间该草稿暂停自动同步；重新保存到本机成功后恢复。已在途请求可能仍保存上一版，但不会将未落盘的新编辑标记为全部同步或允许清除。
- 清除已同步本机副本不会删服务器记录。卸载、换机、清理微信数据可能丢失未同步稿，离线不是备份。
- 重新打开已同步服务器草稿时，以服务器照片引用和说明更新本机照片列表；不恢复 PC 已移除的照片，不用旧说明覆盖服务器补充。未同步／冲突稿仍保留，需人工核对。
- PC 草稿按账号和业务类型逐稿保存，失败附件队列仅当前页内存保留，不能承诺浏览器重启后保留尚未上传的原文件。避免同账号多个标签页同时编辑同一本机草稿。
- 对响应丢失的 PUT，仅当远端正文与原请求完全一致才接纳；服务器字段规范化可能触发保守性冲突，此时人工核对，不自动覆盖。
